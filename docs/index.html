    Single run

    I expected the second worker to help. In these runs it didn't: average went from 9 ms to 22 ms and P99 from 32 ms to 120 ms at roughly 500 req/s. Everything shared one laptop, but I didn't measure which part caused the slowdown. This is one comparison, not a rule that more workers are slower.

    How I measured

    • Load: I ran 50 Locust users aiming for 10 req/s each (500 req/s target). If the API slows down, users wait for responses and the actual request rate drops.
    • Order: I ran six 60‑second tests alternating OFF, ON, ON, OFF, OFF, ON. Before each run, I restarted the API and sent 20 warm‑up requests so the cache was already warm.
    • Machine: Everything ran locally on my Ryzen 7 5700U laptop (Windows, Python 3.13)—the API, Locust, and Docker containers all shared the same machine.
    • Scope: I didn't track SQL query counts or CPU usage per container, and the charts show the median of three runs rather than pooling all requests together.
